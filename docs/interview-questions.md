## 2. 曲面几何模型与标定

**Q2.1 三段式曲面模型是什么？为什么分三段？（★★）**

- 要点：物理曲面（圆柱面近似）按分段长度切成三段（平面-圆柱-平面拼接形态），每段建立虚拟
  平面区域到物理曲面区域的映射；分段是因为整屏统一映射在曲率大处误差放大。
- 追问：段与段接缝处怎么保证连续？→ 参数（宽度、半径、观察距离、分段长度）是整体标定的，
  映射函数在接缝处共享边界条件；标定误差表现为接缝错位，这是标定流程要压的量。

**Q2.2 离轴投影（off-axis projection）和标准透视投影的区别？（★★）**

- 要点：标准透视的视锥对称且视轴垂直于投影面；离轴投影的 frustum 四个面独立（不对称），
  用于眼睛不朝向屏幕中心的"窗口"式映射。曲面屏每段的视口都偏轴，所以逐段用离轴矩阵。
- 追问：能只用平移+裁剪近似吗？→ 平移裁剪是离轴的特例/近似；标定精度要求高时用完整不
  对称 frustum 推导。

**Q2.3 逐像素反投影重映射在哪做？流程是什么？（★★）**

- 要点：发生在光栅化之后的全屏 pass（Slang 计算着色器，post.comp.slang）：对目标（物理曲
  面展平后的）像素，用标定参数反算它在虚拟平面渲染结果上的源坐标，采样重投影。每帧固定
  开销，与场景规模无关。
- 追问：为什么不在投影矩阵里直接做？→ 投影矩阵只能表达线性（平面投影）映射，曲面的非线
  性重投影需要逐像素采样；矩阵阶段做不了。

**Q2.4 四个标定参数（宽度、曲率半径、观察距离、分段长度）怎么标？（★）**

- 要点：已知物理屏规格（出厂参数）+ 观察位姿假设；参数进 Qt 控制台实时可调，改完重启渲
  染生效。误差来源：观察距离假设与真实观众位置不符——所以标定是工程折衷，不做头跟踪。

## 3. Vulkan Multiview 与立体成像

**Q3.1 Multiview 是什么？和"渲染两遍"的区别？（★★）**

- 要点：Vulkan 1.1 核心特性。RenderPass 用 viewMask 声明多层，着色器里 `gl_ViewIndex`
  选相机；几何只提交一次，实现层对每个 view 各执行一遍。省 CPU 记录/提交开销，且**保证
  两眼同帧**——立体显示里两眼不同帧会闪烁。
- 追问：怎么选相机？→ 每眼相机 = 虚拟相机沿基线平移 ±eyeSeparation/2。

**Q3.2 eyeSeparation = 0.065m 有什么依据？（★）**

- 要点：人类平均瞳距 63–65mm。视差方向决定物体在屏前（负视差）/屏后（正视差）。

**Q3.3 按 0 键切换立体/单目是怎么实现的？（★）**

- 要点：运行中切换单双目渲染目标层数（单层/双层），重建 GBuffer 和着色器管线；无需重启，切换时会有短暂重建。

**Q3.4 [基座] 3DGS 是什么？一句话 + 和 NeRF 的区别？（★★）**

- 要点：场景表示为一组各向异性 3D 高斯（位置/协方差/不透明度/球谐颜色），光栅化投影到屏
  幕做 alpha 混合；对比 NeRF：无需逐像素 ray marching，实时性好。本仓库支持从 .ply/.spz
  加载训练好的高斯场。
- 追问：球谐颜色是干嘛的？→ 视角相关的颜色（高阶光照），低阶是漫反射近似。

## 4. Vulkan/OpenGL 互操作与环形缓冲（核心亮点，★★★）

**Q4.1 为什么要做 Vulkan/OpenGL 互操作？不互通怎么走？（★★）**

- 要点：渲染在 Vulkan，四缓冲呈现窗口在 WGL/OpenGL——图像必须跨 API。不互通的路径是
  CPU 回读：VK 拷回系统内存 → memcpy → GL 上传纹理，两次穿越 PCIe。互通后 GPU 内零拷
  贝，且省一次格式往返。

**Q4.2 完整的跨 API 交接流程？（★★★，必考）**

- 要点（按初始化 → 每帧两段说）：
  1. 初始化：VK 分配设备内存 + 图像（导出 capable）→ `vkGetMemoryWin32HandleKHR` 导出
     HANDLE → GL `glImportMemoryWin32Handle`（OPAQUE_WIN32_EXT）→ `glTextureStorageMem2D`
     用导入的内存建纹理 → FBO 完整性检查；两枚二值信号量同样导出/导入。
  2. VK 侧（录制帧）：等待该槽上一次的 `openglDone` → 记录 blit 到共享图像（含布局
     barrier）→ signal `vulkanReady`。
  3. GL 侧（呈现）：`glWaitSemaphore`（vulkanReady，附布局 GENERAL）→ 逐眼 blit 到
     GL_BACK_LEFT/RIGHT → `glSignalSemaphore`（openglDone）→ glFlush → SwapBuffers。
- 追问：内存是谁分配的？→ VK 分配（allocator 管理），GL 只是导入映射；销毁责任在 VK。

**Q4.3 为什么用二值信号量而不是 timeline？（★★）**

- 要点：交接语义是"一次生产-一次消费"的单次握手，二值信号量 wait 成功即自动复位，正好匹
  配；timeline 适合 CPU 参与的多阶段进度同步，跨 API 到 GL 的导入语义也更复杂（GL 侧只对
  接 opaque 二值语义）。
- 追问：fence 不行吗？→ fence 是 CPU 等待 GPU，用 fence 会把呈现节奏耦合到 CPU 轮询，
  丢掉 GPU 侧的异步交接。

**Q4.4 环形缓冲为什么是三槽？两槽、四槽会怎样？（★★★，高频）**

- 要点：在途深度分析。GL/DWM 可能仍在显示槽 k，Vulkan 队列已提交槽 k+1，正在录制槽
  k+2：两槽会让 VK 必须等 GL 展示完才能复写（节奏互锁，掉到最低共同分母）；三槽把两侧节
  奏解耦，谁快谁慢都不覆写在途数据。类比 swapchain 的 image count 选择。
- 追问：怎么保证不覆写在途数据？→ 槽位复用前必须 wait 它上一次的 `openglDone`；这写在
  recordFrame 的槽位协议里（frameNumber % kRingSize 选槽 + 信号量配对）。

**Q4.5 窗口 resize 时会发生什么？（★★★，翻车高发）**

- 要点：`matches(extent, format)` 检测不匹配 → `releaseInterop()`（GL 侧在其上下文内删
  除导入的纹理/FBO/信号量；VK 侧等设备空闲后销毁导出对象）→ `recreate()` 重新分配、导
  出、导入，generation 递增。**陷阱**：两个 API 同时还持有旧资源时销毁 = use-after-free，
  必须双方都越过使用点再销毁。
- 追问：generation 用来干什么？→ 让旧帧号的回调失效，防止 resize 后旧帧写进新槽位。

**Q4.6 共享图像的格式为什么是 RGBA8？源不是别的格式吗？（★★）**

- 要点：渲染目标是浮点格式（曲面 Warp 后的 LDR 结果），导出共享格式固定
  `R8G8B8A8_UNORM`——GL 对它的外部导入兼容性最稳；VK 侧先录一次 `vkCmdBlitImage2` 完
  成格式转换（probe BLIT_SRC/DST 支持后启用）。代价是一次 GPU 内拷贝，仍远便宜于 CPU 回
  读。
- 追问：能不能直接共享浮点格式？→ GL 端对 16F 外部导入支持参差（依赖驱动/扩展），不稳
  妥；探测函数 supportsExternalImage 就是干这个的。

**Q4.7 如果设备不支持外部内存/blit 怎么办？（★）**

- 要点：初始化时 `supportsExternalImage` / `supportsBlit` 探测（format properties2），
  不支持则一开始就 disable 互操作，走 CPU 回读路径——运行中失败（recordFrame/presentInterop
  返回 false）也会 disable 降级。降级是设计好的路径，不是异常。

## 5. WGL 四缓冲与主动立体

**Q5.1 四缓冲和双缓冲的区别？GL_BACK_LEFT/RIGHT 是什么？（★★）**

- 要点：四缓冲 = 左眼前/后 + 右眼前/后；`glDrawBuffer(GL_BACK_LEFT / GL_BACK_RIGHT)`
  分别渲染双眼，`SwapBuffers` 一次翻双面；显示链路发立体同步信号，主动快门眼镜交替遮挡。
- 追问：怎么知道驱动支持？→ 逐个 `DescribePixelFormat` 枚举，检查
  `PFD_STEREO|PFD_DOUBLEBUFFER|PFD_DRAW_TO_WINDOW|PFD_SUPPORT_OPENGL`；本开发机 308 个
  格式中 0 个支持 PFD_STEREO，这正是自动降级被实测触发的原因。

**Q5.2 主动快门式立体显示的原理？（★）**

- 要点：屏幕按刷新率交替显示左右眼，眼镜同步交替遮挡；需要显示链路输出立体同步（quad
  buffer 立体格式），对刷新率敏感（每眼有效帧率减半）。

**Q5.3 为什么 Vulkan 预览窗口要隐藏、由 WGL 窗口接管节奏？（★★）**

- 要点：activeStereoOnlyWindow 模式下两个窗口会双重 VSync 互相拖拽；隐藏 Vulkan 窗口、
  关其 VSync，让 WGL 的 SwapBuffers 独占显示节奏。多显示路径的节奏所有权必须唯一。

## 6. 输出模式与自动降级链

**Q6.1 三种输出模式的决策顺序？每级失败怎么检测？（★★★）**

- 要点（按每帧回调的顺序）：
  1. mode 2（Half-SBS）：Multiview 两层 blit 进普通交换链左右半屏，无需四缓冲，任意显卡
     可跑；立体观感需支持并排格式的设备。
  2. mode 1（四缓冲）：interop recordFrame / presentInterop / CPU 回读 任一失败 →
     disable/hasFailed，不再重试。
  3. mode 0（自动）：先走 1 的完整链，全失败后 `sideBySideOutput->enabled = true` 切到
     2，并恢复主窗口与 VSync。
- 追问：为什么 mode 1 不降级而 mode 0 降？→ 显式选择是调试口径（强制单路径暴露问题）；
  自动模式的职责才是兜底。
- 追问：怎么判断"失败"？→ 每级都有返回值 + hasFailed 标志 + disable 幂等；不是 try/catch。

**Q6.2 说一次你实测触发降级的完整过程。（★★，把日志背下来）**

- 要点：互操作初始化成功（3 个 GPU 共享槽位创建，VK_FORMAT_R16G16B16A16_SFLOAT →
  GL RGBA8）→ WGL 枚举 308 个像素格式、0 个支持 PFD_STEREO → 呈现器失败 → 自动禁用
  GPU 共享 → CPU 回读路径同样依赖四缓冲窗口 → 降级到 Vulkan 并排持续输出。
- 价值：证明降级链是设计出来的、且真实触发过，不是纸面代码。

## 7. 控制台进程模型

**Q7.1 控制台为什么单独进程，而不是一个进程里开两个线程？（★★）**

- 要点：崩溃隔离（渲染器崩了控制台还在，可重启）、生命周期简单（QProcess 启停 + stdout/
  stderr 日志管道）、避免 Qt 事件循环与 Vulkan 渲染循环互相干扰；参数经启动命令行传递，
  "应用并重启"语义清晰。
- 追问：渲染器崩溃控制台怎么表现？→ QProcess 退出信号 → 控制台回收状态，可再次启动。

## 9. [基座] 3DGS 渲染管线（必被问，别让边界背锅）

> 面试官不知道上游边界，这部分必然被问。策略：先给概念级正确答案，主动声明"这层是基座，
> 我通读过但没有改动"，再答细节。以下是要能答到什么程度。

**Q9.1 3DGS 的渲染流程？（★★）**

- 要点：按视线深度排序（GPU 基数排序，仓库里的 vrdx）→ 每个高斯经投影（雅可比近似得屏幕
  空间椭圆）→ 按序 alpha 混合。排序错误 = 混合顺序错 = 透明结果错，所以排序是管线正确性
  前提。
- 追问：排序为什么用基数排序不用快排？→ 百万级元素、键是离散深度、GPU 并行友好；异步提
  交避免阻塞帧。

**Q9.2 这个基座支持哪些路径？（★）**

- 要点：光栅化路径（mesh/vertex）+ 可选 RTX 光追路径 + DLSS（可选宏），由硬件能力探测
  （isSupported）门控启用。

**Q9.3 补课清单（把这几处读一遍就能接住 80% 的基座追问）**

- `src/gaussian_splatting.cpp`：排序→投影→混合的主流程
- `src/splat_sorter_async.cpp` / `third_party/vrdx`：异步基数排序
- `src/shaders/threedgut_*.slang`、`threedgs_raster.*`：高斯投影与光栅化着色器
- `third_party/spz`：压缩格式

## 10. 测量与性能（如果简历保留了实测数字，这节必看）

**Q10.1 简历上的"并排路径 CPU 开销 0.012ms/帧"是怎么测的？测的是谁？（★★★）**

- 要点：帧级统计模块对每帧"呈现调用"计时（steady_clock），输出逐帧 CSV 与
  mean/p50/p95/p99/max；测的是**呈现链路 CPU 侧**（命令记录、跨 API 提交、SwapBuffers），
  不含 GPU 执行时间。分辨率/场景/帧数口径：1920×1080、bicycle、600 帧。
- 追问：GPU 侧怎么测？→ nvutils profiler 的 GPU timer section（渲染部分由基座框架覆盖）。
- 追问：为什么这么小？→ 记录的是 2 次 blit + barrier 的命令提交，合成在 GPU 侧完成；对比
  CPU 回读路径（两次系统内存穿越），这正是互操作的价值证据。

**Q10.2 帧率瓶颈在哪，怎么定位？（★★）**

- 要点：分离"渲染 GPU 时间"与"呈现 CPU 时间"两个口径再谈瓶颈：GPU 瓶颈看 profiler 的
  排序/光栅化 section，CPU 瓶颈看呈现链路统计与提交间隔；呈现类问题优先查 VSync/交换节
  奏（SwapBuffers 阻塞）。

## 11. C++ 与图形基础引申（面试官从项目自然滑向基础）

- Vulkan 三种同步原语的分工：fence（CPU←GPU）、二值信号量（GPU 队列间/跨 API 单次握手）、
  timeline（CPU 可查的多阶段）。（★★）
- 外部内存的销毁顺序：GL 对象必须在其上下文当前时删除（代码里 presentInterop 结束时
  `wglMakeCurrent(nullptr, nullptr)` 之前完成删除）。（★★）
- 回调里大量使用 lambda init-capture（`[x = std::move(x)]`）：为什么？延长生命周期到回调
  异步执行点、按值捕获避免悬垂。（★）
- 固定容量环形结构用 `std::array` 而非 `vector`：容量编译期已知，避免堆分配与间接层。（★）

## 12. 开放设计题（区分度题，答出框架即可）

**Q12.1 如果要支持 VR 头显，架构要怎么改？（★★★）**

- 要点：输出端从 WGL/交换链换成 OpenXR compositor（提交左右眼 texture array）；投影从
  静态标定变为逐帧 head tracking 重算；互操作与环形缓冲的设计可复用——变化的只有"最后
  一公里"，这正是分层设计的收益。

**Q12.2 如果曲面屏换成分辨率/曲率不同的拼接屏，标定流程怎么设计？**

- 要点：参数从全局常量变为每段独立标定集；控制台加交互式标定向导（网格对齐/相机辅助）；
  .csgs 按段存储。
